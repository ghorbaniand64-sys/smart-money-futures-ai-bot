# Hyperliquid Trader Hunter V5.53 + Execution Handoff

This package keeps V5.53 research/audit logic intact and adds a separate execution layer.

## Files

- `hyperliquid_trader_hunter.mjs` — V5.53 research/audit worker. It remains READ-ONLY and never places orders.
- `hyperliquid_execution_engine.mjs` — execution handoff consumer. It revalidates the source trader's current position and the destination account before any order.
- `state/meme_execution_handoff.json` — short-lived handoff generated by V5.53 when at least one `LiveReady` candidate exists.
- `.github/workflows/hyperliquid-trader-hunter.yml` — monitor + execution-handoff workflow.

## Safety defaults

The workflow ships with:

- `EXECUTION_ENABLED=false`
- `EXECUTION_DRY_RUN=true`

Therefore the first deployment cannot submit an order. The engine still performs the full live-data validation and prints the order plan.

## Live gate

An order can only be attempted when all of these are true:

1. V5.53 produced a `LiveReady` candidate.
2. Handoff is fresh (default 90 seconds).
3. Source trader still has the same position and direction.
4. Source entry distance remains within the configured limit.
5. Current market move since the handoff is within the revalidation limit.
6. Destination account has no existing position on the same coin.
7. Destination account has no open order on the same coin.
8. Deterministic client order ID has not already been used.
9. Asset metadata resolves correctly.
10. Notional and account-allocation limits pass.
11. Source leverage does not exceed the configured cap.
12. ATR-based SL/TP are valid and RR meets the configured minimum.
13. In LIVE mode, an agent private key is available.

## Order model

The engine uses Hyperliquid's official JavaScript SDK (`@nktkas/hyperliquid`). A market-like entry is represented by an IOC limit order using the current best bid/ask with configurable slippage. Asset index and size decimals are resolved from `meta()` instead of being hard-coded.

The current package deliberately does **not** submit TP/SL legs yet. It first validates and sends only the entry in LIVE mode. Protective-order attachment should be enabled only after the DRY-RUN cycle has been verified on the user's account and exact risk model.

## Required secrets for eventual LIVE mode

- `TELEGRAM_TOKEN`
- `TELEGRAM_CHAT_ID`
- `HYPERLIQUID_ACCOUNT_ADDRESS`
- `HYPERLIQUID_AGENT_PRIVATE_KEY`

Use an approved Hyperliquid agent wallet for automated signing rather than exposing a master-wallet private key.

## Important

`LiveReady` is a research handoff, not a guarantee. The execution engine always revalidates market/account state immediately before signing.

The engine is intended to be run on a dedicated trading account/sub-account with small limits first.
