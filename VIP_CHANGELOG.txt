V17.3.9 — GMX Allowance Recovery Hardening

Fixes after V17.3.8 still produced relay_failed with:
Error(ERC20: transfer amount exceeds allowance)

Changes:
1. Keeps router-aware GMX SDK approval builder; no hardcoded router address.
2. Normal preflight keeps exact-required approval sizing.
3. On a confirmed GMX relay_failed allowance error, recovery now uses uint256 MAX allowance for the GMX Router.
4. Recovery still performs only ERC20 approval permission; it does not transfer collateral or change position sizing.
5. Recovery rebuilds, re-signs, re-submits exactly once, then requires terminal executed + position verification before counting Executed.
6. Failure telemetry now reports whether recovery was attempted, retry status, recovery approval tx hash, and approval mode.
7. github-runner.mjs uses worker_core.mjs.

IMPORTANT:
This is a live-trading authorization repair. Test with the existing small collateral first.
MAX_UINT256 approval is a spending permission for the GMX Router; it is not a token transfer.
